# Hackathon Management Platform

A full-stack **PHP + MySQL** web application to run hackathons end-to-end: public marketing pages, participant self-service, evaluator scoring, and an admin control center for operations, content, and reporting.

---

## Tech stack

| Layer | Technology |
|--------|------------|
| **Backend** | PHP 8+ (strict types), session-based auth |
| **Database** | MySQL / MariaDB (InnoDB, UTF-8) via **PDO** (`PDO::ATTR_ERRMODE_EXCEPTION`) |
| **Frontend (CDN)** | [Bootstrap 5.3.3](https://getbootstrap.com/), [Bootstrap Icons 1.11](https://icons.getbootstrap.com/) |
| **Custom assets** | `assets/css/app.css`, `assets/js/app.js` |
| **Passwords** | PHP `password_hash()` / `password_verify()` (**bcrypt**, `PASSWORD_DEFAULT`) |
| **File uploads** | Participant/admin uploads (e.g. submissions, gallery) stored under `uploads/` |

There is **no Composer** dependency tree: the project is plain PHP with CDN-delivered CSS/JS.

### “Algorithms” and notable logic

This is primarily a **relational CRUD** application, not an algorithm-heavy codebase. Notable patterns include:

- **Role-based access** (`admin`, `participant`, `evaluator`, `coordinator`) enforced in PHP before loading role-specific layouts.
- **Evaluator scoring**: `INSERT … ON DUPLICATE KEY UPDATE` on `scores` (unique per evaluator/team/criterion) so marks can be saved idempotently.
- **Leaderboard**: SQL aggregation — `SUM(marks)` grouped by team (optionally filtered by event and evaluation round).
- **Activity audit**: `activity_log` table populated on key actions for dashboards and traceability.
- **Feature flags**: `system_settings` key/value toggles (registration open, submission portal, leaderboard visibility, etc.) read via helpers like `setting()`.

## User roles & features

### Public (not logged in)

- **Landing**, **About**
- **Events** listing and **event detail** (dates, venue, rules, etc.)
- **Gallery** (images linked to events)
- **Sign up** / **Login** / **Forgot password** (security question flow)

### Participant (`participant/`)

After login as a participant, typical capabilities include:

- **Dashboard** — registrations, teams, submissions, issues, certificates, activity
- **Event registration** and registration status
- **Teams** — create/join, manage members (where allowed), link to problem statements
- **Problems** — browse/select tracks per event (when enabled)
- **Submissions** — project title, abstract, file upload, repo/demo links, draft/submit workflow
- **Attendance** — check-in style flows where implemented
- **Certificates** — view issued records when available
- **Feedback** — ratings and comments per event
- **Issues** — raise support tickets (technical, registration, etc.)
- **Profile** — profile fields and completion

*(Exact behaviour also depends on **admin settings** — e.g. registration or submission portal may be closed.)*

### Evaluator / Coordinator (`evaluator/`)

- Workspace listing **evaluator assignments** (teams × rounds)
- Enter/update **marks** per criterion (respecting round lock state where enforced)
- Coordinators and admins can also access this area (see `require_role` in `evaluator/index.php`)

### Admin (`admin/`)

Single sidebar-driven console covering:

| Area | Capabilities |
|------|----------------|
| **Dashboard** | KPIs, quick links, recent `activity_log` |
| **Events** | Full CRUD (dates, fees, team size, status, rules) |
| **Registrations** | Search/filter, status & payment notes, CSV export |
| **Teams** | Approve/reject, assign problem, change leader, delete |
| **Problems** | CRUD + CSV bulk import |
| **Labs** | Room CRUD, team–lab assignments, remove assignment |
| **Attendance** | Manual entry, code lookup, filters, row delete, CSV export |
| **Submissions** | Filters, status workflow, full edit, delete |
| **Evaluation** | Rounds, criteria, evaluator assignments, lock/unlock |
| **Leaderboard** | Filters, CSV export |
| **Staff** | Create staff/evaluators/coordinators, edit profile, status, password reset |
| **Issues** | Triage, remarks, delete |
| **Feedback** | Search/filter, delete entries |
| **Certificates** | Templates CRUD, issue records, delete issuance |
| **Announcements** | CRUD for homepage-style notices |
| **Gallery** | Upload, caption/event, update, delete |
| **Settings** | Feature toggles, homepage text, submission deadline display |
| **Reports** | Tabbed summaries with **CSV** for registrations, teams, attendance, submissions, scores, feedback, issues, certificates |

## How to run locally

### 1. Clone or copy the project

Place the folder where your web server can serve PHP (document root), or use the built-in PHP server (see step 5).

### 2. Create the database

```sql
CREATE DATABASE hackathon_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3. Import schema and seed data

From a shell (adjust paths and MySQL user as needed):

```bash
mysql -u root -p hackathon_platform < database/schema.sql
mysql -u root -p hackathon_platform < database/seed.sql
```

On Windows, you can use **phpMyAdmin**, **MySQL Workbench**, or:

```text
mysql -u root -p
SOURCE C:/path/to/Hackathon Management Platform/database/schema.sql;
SOURCE C:/path/to/Hackathon Management Platform/database/seed.sql;
```

### 4. Configure database access

Edit **`config/database.php`**:

- `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`
- **`BASE_PATH`**: leave `''` if the site is at the domain root (e.g. `http://localhost/`).  
  If the app lives in a subfolder (e.g. `http://localhost/hackathon/`), set:

  ```php
  define('BASE_PATH', '/hackathon');
  ```

### 5. Serve the application

**Option A — Apache / Nginx / XAMPP / WAMP**  
Point the virtual host or document root at this project folder. Ensure PHP can write to **`uploads/`** if you use file uploads.

**Option B — PHP built-in server** (development only)

```bash
cd "path/to/Hackathon Management Platform"
php -S localhost:8080
```

Then open `http://localhost:8080`.

### 6. First login

Use any seeded account (see below). Change passwords before production.

| **Participant** | `alice@student.local` (and other `*@student.local` in seed) | `password` |

**Important:** Replace these credentials and regenerate hashes before any public or production deployment.

## Support checklist

- If pages show DB errors: verify `config/database.php` and that `schema.sql` + `seed.sql` ran without errors.
- If links break: check **`BASE_PATH`** matches your URL prefix.
- If uploads fail: check `uploads/` permissions and PHP `upload_max_filesize` / `post_max_size`.
