# SoleCraft — Online Footwear Shopping (PHP + MySQL)

A full-stack **e-commerce storefront** and **admin back office** for selling footwear. The storefront lets customers browse products, manage a cart and wishlist, check out (COD or manual bank transfer), and track orders. The admin panel provides catalog, inventory, sales, customer, and engagement tools with CRUD-style workflows.

## Logic and “algorithms” (business rules)

These are implemented in PHP helpers (mainly `includes/functions.php`) and related pages:

- **Sale price**: `product_sale_price()` — if `discount_price` is set it wins; else if `discount_percent` is set, price is reduced by that percentage; otherwise the base `price` is used.
- **Stock status sync**: `sync_product_stock_flag()` — after quantity changes, `stock_status` is set to `out_of_stock` if quantity ≤ 0, `low_stock` if quantity &lt; 10, otherwise `in_stock`.
- **Order cancellation (stock)**: `restore_order_stock()` — when an order is cancelled (admin), line-item quantities are added back to products and stock flags are recalculated.
- **URL slugs**: `slugify()` — lowercase, non-alphanumeric → hyphens, for product/category/brand URLs.
- **CSRF**: Single token in session; forms POST with `hash_equals` verification.
- **Password hashes**: Bcrypt; seed data uses `$2b$` prefixes normalized in `password_verify_compat()` for PHP’s `$2y$` verifier.

## User (customer) features

- **Account**: Register, login, logout, profile (name, email, mobile, address), change password.
- **Password reset**: Forgot password flow with token storage (`password_resets` table).
- **Storefront**: Home, shop listing with filters, product detail (sizes, pricing, discounts).
- **Cart**: Add/update/remove items; session-backed cart.
- **Wishlist**: Save products (when logged in).
- **Checkout**: Delivery details, payment method (**COD** or **manual** transfer with reference).
- **Orders**: Order history, order detail, cancel when allowed (not shipped/delivered), order confirmation.
- **Payments**: Manual payment submission page linked from checkout when applicable.
- **Invoices**: Printable order summary.
- **Reviews**: Leave reviews (linked to orders where applicable); **My reviews** with edit/delete where supported.
- **Addresses**: Manage delivery addresses (where implemented in `addresses.php`).
- **Contact / feedback**: Contact form storing messages for admin.
- **Notifications**: In-app notifications for order updates (driven by admin/user actions).

---

## Admin features

- **Authentication**: Separate admin login (`admin/login.php`), session gate `require_admin()`.
- **Dashboard**: KPIs (orders, revenue, users, products, low stock, pending reviews, feedback count), recent orders.
- **Catalog CRUD**: Categories, brands, products (create/edit, images, gallery), **stock manager** (quantities; syncs stock flags).
- **Orders**: List/filter, order detail, update **order status** and **payment status**, print invoice; stock restoration on cancel.
- **Manual payments**: Verify payment records and sync order `payment_status`.
- **Users**: List/search, status (active/blocked), delete (constraints may block if orders exist), **user detail** with activity context.
- **Reviews**: Filter by status (pending/approved/hidden), update status, delete.
- **Feedback**: Inbox with search, delete messages.
- **Wishlist report**: Popularity by product.
- **Reports**: Sales by date range, monthly sales, top products, category revenue, order summary, new users, stock listing.
- **Notifications**: Broadcast to users and/or targeted messages by email.
- **Admin profile**: Update name/email and password.

## Database setup

1. Create a MySQL database (example name: `footwear_shop`).
2. **Important:** The bundled SQL files start with:

   ```sql
   USE bosvesedst_footwear_shop;
   ```

   Either:
   - Create a database with that **exact** name, **or**
   - Edit `sql/schema.sql` and `sql/seed.sql` (first line) to use your database name, **or**
   - Remove/replace the `USE ...` line and select the DB in your client before importing.

3. Import **in order**:
   - `sql/schema.sql`
   - `sql/seed.sql`

4. Align PHP config with your MySQL user/password in `config/config.php` (or environment variables below).

### Configuration (`config/config.php`)

Defaults:

- `DB_HOST` = `localhost`
- `DB_NAME` = `footwear_shop`
- `DB_USER` = `root`
- `DB_PASS` = `` (empty)

Optional **environment variables** (override defaults without editing files):

| Variable | Purpose |
|----------|---------|
| `FOOTWEAR_DB_HOST` | MySQL host |
| `FOOTWEAR_DB_NAME` | Database name |
| `FOOTWEAR_DB_USER` | MySQL user |
| `FOOTWEAR_DB_PASS` | MySQL password |
| `FOOTWEAR_BASE_PATH` | URL prefix if not served from domain root (e.g. `/footwear` — no trailing slash) |

## How to run locally

### Option A — XAMPP / WAMP / Laragon (Windows)

1. Copy the project folder into `htdocs` (or your web root), e.g. `htdocs/Online-Footwear-Shopping-Project`.
2. Create the database and import `schema.sql` then `seed.sql`.
3. Set `DB_NAME`, `DB_USER`, `DB_PASS` in `config/config.php` to match phpMyAdmin/MySQL.
4. If the site URL is `http://localhost/Online-Footwear-Shopping-Project/`, set in `config/config.php` via env:

   `FOOTWEAR_BASE_PATH=/Online-Footwear-Shopping-Project`

   or define `BASE_PATH` consistently (see `getenv('FOOTWEAR_BASE_PATH')` in `config.php`).

5. Ensure `uploads/` (and `uploads/products/` if present) is writable by the web server.
6. Open `http://localhost/.../index.php` in a browser.

### Option B — PHP built-in server (quick test)

From the **project root** (where `index.php` lives):

```bash
php -S localhost:8080
```

Then visit `http://localhost:8080/index.php`. You still need MySQL running and `config/config.php` pointing to it.
