# AgriMonitor Pro

Flask web application for **agricultural monitoring** with local **machine learning** (crop recommendation, yield estimation, and risk classification). Farmers use a guided portal to manage farms, log field data, run predictions, and download reports; administrators manage users, datasets, models, and system-wide settings.

---

## Tech stack

- **Backend:** Python 3, Flask 3, Flask-Login, SQLAlchemy (SQLite by default)
- **ML:** pandas, scikit-learn (Random Forest classifier / regressor), pickled models under `instance/models/`
- **Reports:** CSV and PDF (ReportLab), charts (Matplotlib)

| **Prediction history** | Past prediction records |
| **Reports** | Chart views and download personal CSV/PDF reports |

## How to run the project

1. **Clone or open** the project folder.

2. **Create a virtual environment** (recommended):

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

3. **Install dependencies:**

   ```powershell
   pip install -r requirements.txt
   ```

4. **Run the app:**

   ```powershell
   python app.py
   ```

   The dev server listens on **http://127.0.0.1:5000** (host `0.0.0.0`, port `5000`).

5. **First launch:** SQLite DB and folders (`instance/`, `static/uploads/`, `data/`, model/backup dirs) are created automatically. Default parameter ranges and an **admin** user are ensured if missing. If `data/crop_recommendation.csv` exists, a **DatasetFile** row is registered for training.

### Environment variables (optional)

| Variable | Purpose |
|----------|---------|
| `SECRET_KEY` | Flask session secret (default is dev-only) |
| `DATABASE_URL` | Override DB, e.g. `sqlite:///C:/path/agriculture.db` or another SQLAlchemy URL |
| `ADMIN_PASSWORD` | Password assigned when the initial **admin** account is created (see below) |

`python-dotenv` is listed in `requirements.txt` but the app does not load `.env` automatically; set variables in your shell or extend `app.py`/`config.py` to call `load_dotenv()` if you want file-based env.

## Datasets and Kaggle

### Expected CSV columns

Training picks the **active** dataset (admin: “training selected” on an active file) or falls back to `data/crop_recommendation.csv`.

- **Crop recommendation (required for crop model):** column **`label`** (crop name), or the **last column** is treated as the target if `label` is absent. Features are all other columns (numeric + categorical supported).
- **Yield model (optional):** column **`yield_kg_per_ha`** (numeric). If missing or too few rows, yield training is skipped.
- **Risk model (optional):** column **`risk_level`** (categorical). If missing, risk training is skipped.

The sample file in this repo includes:

`N`, `P`, `K`, `temperature`, `humidity`, `rainfall`, `ph`, `label`, `yield_kg_per_ha`, `risk_level`

### Which Kaggle dataset to download

A well-known public dataset that matches the **core crop recommendation** idea (soil nutrients + weather + **pH** + **label**) is:

**[Crop Recommendation Dataset on Kaggle](https://www.kaggle.com/datasets/atharvaingle/crop-recommendation-dataset)**

Typical columns there: `N`, `P`, `K`, `temperature`, `humidity`, `rainfall`, `ph`, `label`.

**Using it in this app:**

1. Download the dataset from Kaggle (account required; use **Download** or the Kaggle CLI).
2. Place or upload the CSV through **Admin → Datasets** (or copy into `data/` and register it).
3. If you need **yield** and **risk** models as in the bundled sample, add columns **`yield_kg_per_ha`** and **`risk_level`** (your own labels/estimates) or continue with crop-only training.

## How to train models

Training always uses the **resolved active CSV** (`get_active_csv_path`: selected `DatasetFile` that is active + training-selected, else `data/crop_recommendation.csv`).

### As administrator

1. Log in as **admin**.
2. Ensure a dataset is selected: **Datasets** → set the correct file as training source.
3. Open **Models** → choose algorithm where offered → submit **Train**.  
   This trains **crop** (always), **yield** (if `yield_kg_per_ha` exists and enough rows), and **risk** (if `risk_level` exists).

### As a regular user

1. Log in as a farmer.
2. Go to **Datasets** (or the ML section linked from the portal).
3. Click **Train models** (POST to `/user/ml/train`).  
   Same three-model behavior as admin; new rows are stored in `TrainedModel` and marked default for crop/yield/risk as applicable.

Models are saved under **`instance/models/`** as `.pkl` files. The **default** flags determine which files the prediction pages load.
