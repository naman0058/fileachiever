# Bus Pass Management System – Project Functionality 

## 1. Project Overview

The Bus Pass Management System is a web-based application developed to simplify the process of applying for, issuing, managing, and verifying bus passes.

Tech Stack 

Php and mysql

The system contains three main modules:

1. Admin Module
2. Vendor Module
3. User Module

The project will use a simple database to store user details, bus pass applications, routes, pass categories, validity dates, and approval records.

---

# 2. Admin Functionality

The Admin will have complete control over the system and will manage users, vendors, routes, pass applications, and reports.

## 2.1 Admin Login

* Admin can log in using a registered username and password.
* The system will validate the login credentials.
* Incorrect login details will display an error message.
* Admin can securely log out from the system.

## 2.2 Admin Dashboard

The admin dashboard will display:

* Total registered users
* Total registered vendors
* Total bus pass applications
* Total approved applications
* Total rejected applications
* Total pending applications
* Total active bus passes
* Total expired bus passes

## 2.3 Manage User Accounts

Admin can:

* View all registered users
* Search users by name, email, phone number, or user ID
* View complete user details
* Edit user information
* Activate or deactivate a user account
* Delete a user account
* View bus pass applications submitted by a particular user

## 2.4 Manage Vendor Accounts

Admin can:

* Add a new vendor
* View all registered vendors
* Edit vendor details
* Activate or deactivate a vendor account
* Delete a vendor account
* Assign a username and password to the vendor
* View applications processed by a vendor

Vendor details may include:

* Vendor name
* Contact person name
* Email address
* Phone number
* Address
* Username
* Account status

## 2.5 Manage Bus Routes

Admin can:

* Add a new bus route
* View all available routes
* Edit route details
* Delete a route
* Activate or deactivate a route

Route details may include:

* Route number
* Source location
* Destination location
* Main stops
* Route status

## 2.6 Manage Bus Stops

Admin can:

* Add bus stops
* Edit bus stop names
* Delete bus stops
* Assign stops to a route
* Arrange stops in route order
* View all stops available under a selected route

## 2.7 Manage Pass Categories

Admin can create and manage different bus pass categories, such as:

* Student Pass
* General Pass
* Employee Pass
* Senior Citizen Pass

Admin can:

* Add a pass category
* Edit pass category details
* Delete a pass category
* Activate or deactivate a category
* Define the validity period
* Set the pass amount

## 2.8 Manage Pass Duration

Admin can manage pass duration options such as:

* Monthly pass
* Quarterly pass
* Half-yearly pass

For each duration, the admin can define:

* Duration name
* Number of valid days
* Pass amount
* Status

## 2.9 View Bus Pass Applications

Admin can view all submitted applications.

The application list will show:

* Application number
* Applicant name
* Pass category
* Selected route
* Source stop
* Destination stop
* Application date
* Application status
* Assigned vendor

Admin can filter applications by:

* Pending
* Approved
* Rejected
* Issued
* Expired
* Date
* Pass category
* Route

## 2.10 Assign Applications to Vendors

Admin can:

* Select a pending application
* Assign the application to a vendor
* Change the assigned vendor
* View the vendor currently handling the application

## 2.11 Approve or Reject Applications

Admin can directly process an application when required.

Admin can:

* View applicant details
* View submitted information
* Approve the application
* Reject the application
* Enter a rejection reason
* Return the application for correction
* Update the application status

## 2.12 Issue Bus Pass

After approval, the admin can generate a bus pass containing:

* Pass number
* User name
* User photograph, if uploaded
* Pass category
* Route number
* Source stop
* Destination stop
* Issue date
* Valid-from date
* Expiry date
* Pass status

## 2.13 Manage Issued Bus Passes

Admin can:

* View all issued passes
* Search a pass by pass number or user name
* View pass details
* Cancel a pass
* Mark a pass as expired
* Reissue a corrected pass
* Print the bus pass
* View active and expired passes separately

## 2.14 Application Status Management

Admin can manage the following application statuses:

* Submitted
* Under Review
* Correction Required
* Approved
* Rejected
* Pass Issued
* Expired
* Cancelled

## 2.15 View User Feedback and Complaints

Admin can:

* View feedback submitted by users
* View complaints
* Search complaints by user or date
* Update complaint status
* Add a response
* Mark a complaint as resolved

## 2.16 Reports

Admin can view simple reports such as:

* User registration report
* Vendor report
* Application report
* Approved application report
* Rejected application report
* Pending application report
* Active pass report
* Expired pass report
* Route-wise pass report
* Category-wise pass report
* Date-wise application report

## 2.17 Change Password

Admin can:

* Enter the current password
* Enter a new password
* Confirm the new password
* Update the login password

# 3. Vendor Functionality

The Vendor will review assigned applications, verify user details, approve or reject applications, and issue bus passes.

## 3.1 Vendor Login

* Vendor can log in using the username and password provided by the admin.
* The system will validate login credentials.
* Deactivated vendors will not be allowed to log in.
* Vendor can log out securely.

## 3.2 Vendor Dashboard

The vendor dashboard will display:

* Total assigned applications
* Pending applications
* Applications under review
* Approved applications
* Rejected applications
* Passes issued by the vendor
* Applications requiring correction

## 3.3 View Assigned Applications

Vendor can view only the applications assigned by the admin.

The application list will show:

* Application number
* Applicant name
* Pass category
* Selected route
* Application date
* Current status

## 3.4 Search and Filter Applications

Vendor can search applications by:

* Application number
* Applicant name
* Phone number
* Pass category
* Route

Vendor can filter applications by:

* Pending
* Under Review
* Approved
* Rejected
* Correction Required
* Pass Issued

## 3.5 View Applicant Details

Vendor can view:

* Applicant name
* Date of birth
* Gender
* Email address
* Phone number
* Residential address
* Identity information
* Pass category
* Route
* Source stop
* Destination stop
* Uploaded photograph
* Submitted application details

## 3.6 Verify Application Information

Vendor can check whether:

* Required fields are completed
* User details are correct
* Route and stop selection is valid
* Pass category is appropriate
* Photograph has been uploaded
* Identity information has been entered
* Student or employee information is provided where applicable

## 3.7 Request Correction

If an application is incomplete, the vendor can:

* Select “Correction Required”
* Enter the correction reason
* Send the application back to the user
* View the corrected application after resubmission

Possible correction reasons may include:

* Incorrect personal details
* Missing photograph
* Invalid route selection
* Incomplete address
* Missing identity information
* Incorrect pass category

## 3.8 Approve Application

Vendor can approve an application after verification.

After approval:

* Application status will change to “Approved”
* Approval date will be stored
* Vendor name will be recorded
* The application will become available for pass issuance

## 3.9 Reject Application

Vendor can reject an application.

The vendor must:

* Select a rejection reason
* Add remarks
* Confirm rejection

The user will be able to view the rejection reason.

## 3.10 Generate Bus Pass

After approval, the vendor can generate the bus pass.

The generated pass will contain:

* Pass number
* User name
* Photograph
* Pass category
* Route
* Source stop
* Destination stop
* Issue date
* Validity start date
* Expiry date
* Pass status

## 3.11 Print Bus Pass

Vendor can:

* Open the generated bus pass
* View it in printable format
* Print the pass
* Reprint an already issued pass

## 3.12 View Issued Passes

Vendor can view all passes issued by them.

The vendor can search by:

* Pass number
* User name
* Issue date
* Route
* Pass category

## 3.13 View Application History

Vendor can view the complete processing history of an application, including:

* Submission date
* Review date
* Correction request
* Resubmission date
* Approval or rejection date
* Pass issue date

## 3.14 Update Profile

Vendor can update:

* Contact person name
* Phone number
* Email address
* Address

## 3.15 Change Password

Vendor can:

* Enter the current password
* Enter a new password
* Confirm the new password
* Save the updated password

# 4. User Functionality

The User can register, apply for a bus pass, check the application status, correct an application, and view or print the issued bus pass.

## 4.1 User Registration

A new user can create an account by entering:

* Full name
* Email address
* Phone number
* Date of birth
* Gender
* Residential address
* Username
* Password
* Confirm password

The system will:

* Check whether the email or username already exists
* Validate required fields
* Save the user details
* Display a successful registration message

## 4.2 User Login

* User can log in using a username or email and password.
* Invalid login details will display an error message.
* Deactivated users will not be allowed to log in.
* User can securely log out.

## 4.3 User Dashboard

The user dashboard will display:

* Total submitted applications
* Pending applications
* Approved applications
* Rejected applications
* Active passes
* Expired passes
* Latest application status

## 4.4 Manage Profile

User can:

* View profile details
* Edit full name
* Update phone number
* Update address
* Update date of birth
* Update gender
* Upload or change profile photograph

## 4.5 Apply for a New Bus Pass

User can submit a bus pass application by entering:

### Personal Details

* Full name
* Date of birth
* Gender
* Email address
* Phone number
* Residential address

### Pass Details

* Pass category
* Pass duration
* Route
* Source stop
* Destination stop
* Required start date

### Identification Details

* Identity type
* Identity number
* Photograph

For a student pass, additional fields may include:

* College name
* Course name
* Semester or year
* Enrollment number

For an employee pass, additional fields may include:

* Company name
* Employee ID
* Designation

## 4.6 Application Validation

Before submission, the system will check:

* All required fields are completed
* Source and destination stops are different
* The selected stops belong to the selected route
* Required photographs or details are provided
* The user does not already have a duplicate pending application for the same pass

## 4.7 Application Preview

Before final submission, the user can:

* Review entered information
* Verify route details
* Check pass category
* Check selected duration
* Edit incorrect information
* Confirm final submission

## 4.8 Submit Application

After submission:

* A unique application number will be generated
* Application status will be set as “Submitted”
* Submission date will be stored
* The user will see a confirmation message

## 4.9 View My Applications

User can view all submitted applications.

The list will display:

* Application number
* Pass category
* Route
* Submission date
* Application status
* Validity period
* Available action

## 4.10 Track Application Status

User can check whether the application is:

* Submitted
* Under Review
* Correction Required
* Approved
* Rejected
* Pass Issued
* Expired
* Cancelled

## 4.11 Correct and Resubmit Application

When the status is “Correction Required,” the user can:

* View the correction reason
* Edit the required fields
* Upload a new photograph where required
* Review the corrected details
* Resubmit the application

After resubmission, the status will change to “Submitted” or “Under Review.”

## 4.12 View Rejection Reason

If the application is rejected, the user can:

* View the rejection reason
* View vendor remarks
* Submit a new application after correcting the issue

## 4.13 View Issued Bus Pass

After pass issuance, the user can view:

* Pass number
* User name
* Photograph
* Pass category
* Route
* Source stop
* Destination stop
* Issue date
* Valid-from date
* Expiry date
* Pass status

## 4.14 Print Bus Pass

User can:

* Open the bus pass in printable format
* Print the bus pass
* Save the printable page using the browser’s print option

## 4.15 View Pass Validity

The system will show whether the pass is:

* Active
* Expired
* Cancelled

The remaining validity period may also be displayed.

## 4.16 Apply for Pass Renewal

A user can renew an expired or soon-to-expire pass by:

* Selecting an existing pass
* Clicking “Apply for Renewal”
* Reviewing previous details
* Updating changed information
* Selecting a new validity period
* Submitting the renewal application

The renewal will be treated as a new application linked to the previous pass.

## 4.17 Cancel Pending Application

User can cancel an application only when its status is:

* Submitted
* Pending
* Correction Required

Approved or issued applications cannot be cancelled directly by the user.

## 4.18 Submit Feedback

User can submit feedback by entering:

* Subject
* Feedback message
* Rating
* Submission date

## 4.19 Submit Complaint

User can submit a complaint containing:

* Complaint subject
* Complaint description
* Related application number, if applicable
* Complaint date

User can view whether the complaint is:

* Submitted
* Under Review
* Resolved

## 4.20 Change Password

User can:

* Enter the current password
* Enter a new password
* Confirm the new password
* Save the updated password

## 4.21 Forgot Password

A simple college-level forgot-password function can use security questions.

The user can:

* Enter the registered username or email
* Answer the saved security question
* Set a new password

This avoids the requirement for email or OTP services.

# 5. Bus Pass Application Workflow

The complete system workflow will be:

1. User creates an account.
2. User logs in.
3. User completes the bus pass application form.
4. User selects the pass category, route, source, destination, and duration.
5. User previews and submits the application.
6. The system generates an application number.
7. Admin views the submitted application.
8. Admin assigns the application to a vendor.
9. Vendor reviews the application.
10. Vendor approves, rejects, or requests corrections.
11. User corrects and resubmits the application when required.
12. Vendor approves the corrected application.
13. Vendor or admin generates the bus pass.
14. User views and prints the issued pass.
15. The system marks the pass as expired after the validity date.

# 7. Final Minor Project Scope

The completed project should include:

* Admin, Vendor, and User login
* User registration
* User profile management
* Vendor management
* Route and bus stop management
* Pass category and duration management
* Bus pass application form
* Application assignment to vendors
* Application approval and rejection
* Application correction and resubmission
* Bus pass generation
* Printable bus pass
* Application status tracking
* Pass renewal
* Complaint and feedback management
* Basic reports
* Password management

The project will not include GPS tracking, live bus location, third-party payment gateways, SMS services, email services, biometric verification, external transport APIs, or other complex integrations.
