# NeuroScan — Brain Tumor Detection (Flask + ML)

A college-style web application for **brain MRI classification** using **Python**, **Flask**, **SQLite**, and **scikit-learn** (OpenCV feature extraction). All training and inference run **locally**; there is **no third-party inference API**.

> **Disclaimer:** This project is for **education and demonstration** only. It is **not** a medical device and must not be used for clinical diagnosis.

---

## Tech Stack

| Layer | Technology |
|--------|-------------|
| Backend | Python 3, Flask |
| Database | SQLite (`instance/app.db`) |
| Frontend | HTML, CSS, Bootstrap 5 |
| ML | OpenCV (HOG, histogram, edges), scikit-learn `RandomForestClassifier` |
| Reports | fpdf2 (PDF), generated HTML reports |
| Auth | Sessions, password hashing (Werkzeug) |

---

## Complete Project Features

- **Secure authentication:** Hashed passwords, user vs admin roles, separate admin session.
- **MRI workflow:** Upload → preview → predict → store result → history → PDF/TXT export.
- **Machine learning:** Train/retrain from labeled folders; model saved as `instance/tumor_model.joblib`; metrics and confusion matrix in admin.
- **Reporting:** User-level prediction reports; admin HTML reports (user-wise, date-wise, overall).
- **Feedback:** Contact form messages visible in admin.
- **Settings:** Admin can adjust allowed extensions, max upload size, and active model path.

## Functionality Highlights

- **Passwords:** Stored with Werkzeug hashing; never plain text.
- **Sessions:** Flask sessions; users and admins use distinct session keys.
- **Validation:** Server-side checks on forms and uploads.
- **Storage:** MRI files on disk; metadata in SQLite (`Prediction`, `User`, `Feedback`, `SystemSetting`).
- **ML pipeline:** Features = HOG (on equalized grayscale) + normalized intensity histogram + statistics + edge density; classifier = RandomForest with balanced subsampling for class imbalance.
- **Binary vs multiclass:** If both `yes` and `no` folders exist (see below), training uses **binary** labels (displayed as **Tumor** / **No Tumor**). Otherwise, training uses **multiclass** folders under `Training/`.

## How to Run

### 1. Prerequisites

- Python 3.10+ recommended  
- pip

### 2. Install dependencies

From the project root:

```bash
pip install -r requirements.txt
```

### 3. (Optional) Seed demo data

Creates the SQLite database, sample users, sample predictions, feedback, and a **demo** model (only when no real training data is present):

```bash
python seed_data.py
```

**Default credentials after seed:**

| Role | Username | Password |
|------|----------|----------|
| Admin | `admin` | `Admin@123` |
| User | `alice_c` (and others) | `User@123` |

### 4. Start the server

```bash
python run.py
```

Open a browser at **http://127.0.0.1:5000** (default in `run.py`).

### 5. URLs

| Page | Path |
|------|------|
| Landing | `/` |

**Production:** Set a strong `SECRET_KEY` environment variable and use a production WSGI server (e.g. Gunicorn); change default passwords.

## How to Train the Model

Training **reads images from disk** and writes:

- `instance/tumor_model.joblib` — serialized model + label encoder  
- `instance/training_metrics.json` — accuracies, report, confusion matrix data  
- `static/generated/confusion_matrix.png` — plot (if matplotlib succeeds)

### Dataset layout (choose one)

**A — Binary (tumor vs no tumor)** — use **both** `yes` and `no`, each with at least some images:

1. **Option 1 — under project dataset root**

   ```
   brain_tumor_dataset/yes/   ← tumor images (JPG/PNG)
   brain_tumor_dataset/no/    ← non-tumor images
   ```

2. **Option 2 — under `Training`**

   ```
   brain_tumor_dataset/Training/yes/
   brain_tumor_dataset/Training/no/
   ```

The trainer prefers **root-level** `yes`/`no` if both directories exist; otherwise it uses `Training/yes` and `Training/no`.

**B — Multiclass** (if you are **not** using binary `yes`/`no` with images in both):

```
brain_tumor_dataset/Training/glioma/
brain_tumor_dataset/Training/meningioma/
brain_tumor_dataset/Training/pituitary/
brain_tumor_dataset/Training/no_tumor/
```

You need **at least two classes** with images for training to succeed.

### Train from the UI

1. Log in as **admin** (`/admin/login`).
2. Go to **Dataset** to confirm counts or upload more images into the right folders.
3. Open **Train model** and click **Start training**.
4. Check **Model performance** for validation accuracy and confusion matrix.

### After code or feature changes

If the feature vector size changes, an old `tumor_model.joblib` may be incompatible. **Retrain** from **Train model** after updating the project.

### Notes

- **More balanced data** (`yes` vs `no` counts) usually improves generalization.
- **Demo model** (`seed_data.py` or auto-demo when no data exists) is **not** clinically meaningful — always train on your real folders for serious experiments.
- If `fpdf` / `fpdf2` conflicts appear, use only **fpdf2** (see package documentation).
