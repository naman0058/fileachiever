# Fake News Detection

Django web application that classifies news as **Real** or **Fake** using a hybrid machine-learning pipeline. Users sign up, run checks on pasted text or article URLs, and review history and charts in a dashboard. Staff users and the Django admin get cross-user visibility and management tools.

---

## What this project does

- **Training:** Loads a labeled CSV (e.g. Kaggle-style `text` + `label`), preprocesses text, vectorizes with **TF-IDF**, trains **Logistic Regression** and **Random Forest**, then saves artifacts under `ml_artifacts/` (`tfidf.joblib`, `logreg.joblib`, `rf.joblib`, `meta.json`).
- **Inference:** New text is cleaned the same way, transformed with the saved vectorizer, and both models output class probabilities. The app **averages** the two models’ probabilities (hybrid ensemble) and picks **Fake** if the averaged fake probability is ≥ **0.4**, otherwise **Real**. Per-model probabilities are stored on each prediction for transparency.
- **URL checks:** Fetches HTML with **requests**, extracts article text with **BeautifulSoup** (and **lxml**), optionally runs **URL authenticity** heuristics, and may infer country hints from the URL for reporting.

## Algorithms and libraries

| Area | Technology |
|------|------------|
| Web framework | **Django** (routing, ORM, auth, admin, templates) |
| ML models | **scikit-learn** — `TfidfVectorizer`, `LogisticRegression`, `RandomForestClassifier`; `train_test_split`, `accuracy_score`, `confusion_matrix`, `classification_report` |
| NLP preprocessing | **NLTK** — stopwords (with negation words retained), **WordNet** lemmatization |
| Serialization | **joblib** — load/save vectorizer and models |
| Data | **pandas**, **numpy** |
| HTTP / HTML | **requests**, **beautifulsoup4**, **lxml** |
| Charts (dashboard) | **matplotlib**, **seaborn** |
| Configuration | **python-dotenv** (optional `.env`; see `.env.example`) |

Full dependency list: `requirements.txt`. Use the same **scikit-learn** major line for training and serving so pickled models load correctly.

## User features

| Feature | Description |
|---------|-------------|
| **Registration** (`/register/`) | Username, email, password; auto login and redirect to home. |
| **Login / logout** (`/login/`, `/logout/`) | Standard session auth. |
| **Password reset** (`/password-reset/`, …) | Email-based reset; if SMTP fails, the app can fall back to saving messages under the `emails/` folder (see app behavior and `EMAIL_SETUP.md` / `.env.example`). |
| **Landing page** (`/`) | Public info; detection form and latest checks only when **logged in**. Optional **country**, **India state**, and **news category** fields on submit for richer reports. |
| **Detection** (`/detect/`, POST) | **Text:** minimum ~20 characters. **URL:** fetch and extract text (minimum ~50 characters). Shows label, confidence, hybrid and per-model probabilities, cleaned-text preview, and URL authenticity info when applicable. Each run is stored in the database for the current user. |
| **Dashboard — overview** (`/dashboard/`) | Totals, fake vs real breakdown, model trained/not trained, latest records (own data only for normal users). |
| **Dashboard — history** (`/dashboard/history/`) | Search (text, URL, prediction, country, state, category); up to 200 rows; delete own records. |
| **Dashboard — reports** (`/dashboard/reports/`) | Charts (e.g. label distribution, detections over time, breakdowns by category/country where data exists); filters by date, country, category, prediction, input type. |
| **Static pages** | **About** (`/about/`), **Contact** (`/contact/`). |
| **Health** | `GET /health/` for a simple readiness-style check. |

**Scope:** Regular users only see **their own** `PredictionResult` rows in the dashboard. They can only delete their own rows.

## Admin and staff features

| Feature | Description |
|---------|-------------|
| **Django admin** (`/admin/`) | **Superuser/staff only.** Manage all `PredictionResult` entries: list, search, filter (user, input type, prediction, date), add/change/delete. |
| **Staff dashboard** | Users with `is_staff` see **all users’** data on overview, history, and reports, with extra columns (e.g. **User**) and filters such as filtering reports by **user id**. Staff can delete any record visible in their queryset. |
| **Management commands** | `train_model` — train from CSV (see below). `seed_data` — insert dummy rows (optionally `--user USERNAME`). `migrate`, `createsuperuser` — standard Django. |

## Default login credentials

**This repository does not ship with default usernames or passwords.** There is no pre-seeded admin account in code.

1. **Django admin (superuser):** create one locally:
   ```bash
   python manage.py createsuperuser
   ```
   Then sign in at `http://127.0.0.1:8000/admin/`.

2. **Normal app users:** register at `http://127.0.0.1:8000/register/` (or use the registration link on the site).

If you use **password reset** email, configure SMTP (or file backend) using `.env.example` as a template—do not commit real secrets.

## How to run the project

### Prerequisites

- **Python 3.x** (3.10+ recommended)
- A terminal in the project root (folder that contains `manage.py`)

### 1) Virtual environment and dependencies

```bash
python -m venv .venv
```

Activate:

- **Windows:** `.venv\Scripts\activate`
- **Linux / macOS:** `source .venv/bin/activate`

```bash
pip install -r requirements.txt
```

(Optional) Copy `.env.example` to `.env` and adjust `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, hosts, and email settings for your environment.

### 2) Database

```bash
python manage.py migrate
```

### 3) Dataset and training

Place a labeled CSV at `data/news.csv` (see `data/README_DATASET.txt` for expected columns). Quick demo without a full dataset:

```bash
python manage.py train_model --csv data/sample_news.csv
```

Full training:

```bash
python manage.py train_model
```

### 4) Optional demo data

```bash
python manage.py seed_data
# Attach rows to a specific user after they register:
python manage.py seed_data --user YOUR_USERNAME
```

### 5) Admin account

```bash
python manage.py createsuperuser
```

### 6) Run the server

```bash
python manage.py runserver
```

## Notes

- **URL detection** depends on live sites; extraction may fail for paywalls or heavy JavaScript pages—users can fall back to pasting text.
- **Production:** set `DJANGO_DEBUG=0`, a strong `DJANGO_SECRET_KEY`, and `DJANGO_ALLOWED_HOSTS` via `.env` or your host’s environment; review Django’s deployment checklist.
- More feature detail is also in `FEATURES.md`; ML and preprocessing narrative in `functionality.txt`.
